# The Open-Source French Tutor

## Speech

| Layer | Tool | Goal |
|------------|--------------|--------------|
|Pipeline Orchestration| Pipecat (Python) or LiveKit| Handles the asynchronous routing of audio streams, WebRTC connections, and interruption handling (so the AI stops talking when you speak over it)|
|Speech-to-Text (STT)| Whisper Large V3 Turbo| The gold standard for multilingual transcription. The Turbo variant cuts down processing time drastically while maintaining high accuracy for learner accents|
|The Brain (LLM)| Mistral (7B / NeMo / Large)| Built by a French company, Mistral models have an innate, deeply nuanced grasp of French syntax, idioms, and cultural context that often surpasses general open-source models|
|Text-to-Speech (TTS)| Voxtral TTS or Qwen3-TTS|Voxtral is an exceptional open-source model optimized for European languages, delivering natural French intonation. Qwen3-TTS is a great alternative if you want precise style/emotion control|

### The Real-Time Voice Loop

To make speaking practice feel natural, your agent needs to execute these phases sequentially and with sub-second latency.

1. Voice Activity Detection (VAD):
Phase 1: Input Isolation.Use Silero VAD (usually bundled with Pipecat) to detect when you start and stop talking. This prevents the agent from triggering when you simply breathe, sigh, or pause to think of a word.

1. Streaming Speech-to-Text:Phase 2: Transcription.  Stream your audio into Faster-Whisper. Instead of waiting for you to finish a whole paragraph, it processes audio chunks on the fly to prepare the text for the LLM.

1. Grammar Correction & Response:Phase 3: LLM Logic. Pass the text to Mistral. Your system prompt should instruct the model to operate in two steps: (1) Secretly evaluate your French grammar/vocabulary and log corrections, and (2) Formulate a conversational reply in French adapted to a B1/B2 target level.

1. Audio Synthesis:Phase 4: Native Playback.Stream the text response into Voxtral TTS. By using a streaming TTS system, the agent can start speaking the first words of its sentence while the rest of the response is still being generated by the LLM.

### Guard Rails

The "Tutor-in-the-Loop" Prompting Strategy.
The AI shouldn't just chat, it should  to track user progress against the CEFR (Common European Framework of Reference) guidelines.

- The Correction Script: The LLM should wrap structural corrections in specific UI tags. For example, if you say "Je visiterai mon ami" (incorrect French for visiting a person), the LLM should reply via voice with the correct conversational flow, but pass a text-based flag back to the UI: [CORRECTION: On dit "rendre visite à quelqu'un" ou "aller voir quelqu'un"].

- Progressive Difficulty: The agent should have instructions to use clean, standard, slightly slower French (A1/A2 level). As your response accuracy increases, program the agent to introduce complex structures required for B2, such as the subjunctive mood (il faut que tu saches) and conditional hypotheses.

### Recommended Open-Source Chat UIs


1. Chainlit (Python)
Why it fits: This is the best choice for your stack. It is entirely Python-based, meaning it integrates perfectly with the backend code you would write for your voice agent.

- Key Feature: Chainlit has native support for "Step" tracking. This allows the UI to split the AI's response: one part can be the conversational reply in French, and another collapsible part can display the grammar corrections without cluttering the chat window.

2. Open WebUI or LibreChat
Why it fits: If you want a full, production-grade clone of ChatGPT that runs locally on your machine.

- Key Feature: These platforms connect directly to local LLM runners like Ollama. You don't have to code a UI at all; you simply write your system prompt inside the web interface, select your local Mistral model, and start chatting.

## Implementation Strategy 

- State Management: Using an agent framework like LangGraph or a simple session state to store a running list of mistakes. Repeating the same grammar error (e.g., misusing pendant vs pour), the agent should flag it as a persistent issue.

- The Evaluation Prompt: The LLM should return a structured JSON response instead of plain text. The JSON should separate the conversational text from the corrections.

A robust prompt schema for your LLM background should look like this:

``` json
{
  "tutor_reply": "Le message de conversation suivant en français...",
  "corrections": [
    {"error": "J'ai visité mon ami", "correction": "Je suis allé voir mon ami / J'ai rendu visite à mon ami", "rule": "On utilise 'visiter' pour les lieux, et 'rendre visite à' pour les personnes."}
  ],
  "estimated_level": "B1"
}
```

## Development Plan

### Phase 1: Environment & Infrastructure Setup

- Before writing the core logic, establish local development environment and get open-source models running.

- Initialize the Project: Create a new Python virtual environment to manage dependencies cleanly.

- Install a Local Model Runner: Download and install Ollama, allowing runing  and communication with the LLM entirely on the local machine without API costs.

- Pull the Core LLM: Download the Mistral model by running `ollama run mistral` in the terminal, this will act as the brain for both text and voice.

- Install Core Libraries: Install primary Python packages using pip: chainlit (for the text UI), pipecat-ai (for the voice orchestration), and langgraph (for state management).

### Phase 2: Build the Text & Evaluation Engine (Writing Practice)

- Start with the text-based interface. It is easier to debug the LLM's evaluation logic in text before introducing the complexities of real-time audio.

- Define the System Prompt: Write a strict system prompt instructing Mistral to act as a TEF/TCF evaluator. Mandate that it assesses input against A1-B2 CEFR standards.

- Enforce JSON Outputs: Configure model calls to output a structured JSON schema containing three specific keys: `tutor_reply` (the conversational response), `corrections` (an array of grammar/vocabulary fixes), and `estimated_level`.

- Set Up State Management: Implement a simple session memory so the agent remembers the context of the conversation and can track repeated grammatical errors over a single session.

- Build the Chainlit UI: Write the Chainlit script to render the chat. Map the `tutor_reply` to the main chat bubbles and render the `corrections` array into collapsible UI elements alongside the chat.

### Phase 3: Develop the Voice Pipeline (Speaking Practice)

- Once the text logic is solid, build the asynchronous audio pipeline for real-time conversation.

- Implement Voice Activity Detection: Set up Silero VAD to monitor the microphone input and accurately slice the audio stream when you stop speaking.

- Integrate Speech-to-Text (STT): Connect the sliced audio output from the VAD to Faster-Whisper to transcribe your spoken French into text in real-time.

- Route to the LLM: Pass the transcribed text into the exact same Mistral evaluation logic built in Phase 2.

- Integrate Text-to-Speech (TTS): Connect the conversational output from Mistral (tutor_reply) to a local TTS engine like Voxtral or Qwen3-TTS.

- Orchestrate with Pipecat: Wrap these four components inside a Pipecat pipeline to handle the asynchronous streaming, ensuring the TTS starts playing back immediately while the LLM is still generating the end of its sentence.

### Phase 4: Exam Specific Tuning & Testing

- With both interfaces functional, tune the application specifically for A1.1 to B2 level.

- Create Scenario Presets: Hardcode specific TEF/TCF scenarios into your app (e.g., "Argue against a parking ticket," "Inquire about a job posting").

- Implement Difficulty Scaling: Add a toggle in your UI to switch the agent's target level. At A1, the agent should use simple vocabulary and speak slowly. At B2, it should use complex idioms, the subjunctive mood, and standard native speaking speed.

- Test the Latency: Run the voice pipeline and measure the delay between your final spoken word and the AI's first spoken word. If it exceeds 1.5 seconds, optimize by utilizing smaller Whisper models (like the "base" or "turbo" variants) or adjusting your streaming chunk sizes.
